# Preliminary results — 2026-08-10

> Superseded for performance comparison by the
> [Phase 1 strong-baseline results](phase1-results-2026-08-10.md). The table
> below remains the original NumPy-oracle measurement and must not be treated
> as a comparison with the strongest CPU implementation.

Hardware: NVIDIA RTX A4000, 16 GB, compute capability 8.6. The fused-linear
workload uses 32 alternatives and 16 float32 chooser features. Results are
medians after workload-sized warm-up; all raw timing samples are written by the
benchmark harness.

These are microbenchmark results against the readable NumPy correctness oracle,
not Sharrow or full-ActivitySim speedups. The transfer-inclusive measurement
copies features, coefficients, constants, availability, and draws to the GPU and
copies choices and logsums back. The resident measurement assumes model arrays
already reside on the GPU.

The CPU reference materializes a 12.8 MB utility matrix at 100,000 choosers and
a 128 MB matrix at 1,000,000 choosers. The fused CUDA kernel does not allocate
that global utility matrix.

## ActivitySim `choice_maker` isolation result

For 100,000 choosers and 32 float64 probability columns, ActivitySim 1.4's warm
Numba `choice_maker` took 2.515 ms. The exactly compatible CUDA kernel took
2.591 ms including transfers (0.97x, slightly slower) and 0.212 ms with inputs
GPU-resident (11.86x faster), with zero choice mismatches.

This negative transfer-inclusive result is important: offloading only the final
sampling operation is not worthwhile. The performance case depends on fusing
utility evaluation and logsum generation and retaining model arrays on device,
which is the architecture ChoiceForge is pursuing.
